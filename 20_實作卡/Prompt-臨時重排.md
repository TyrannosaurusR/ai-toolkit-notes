> [!summary] TL;DR
> 1 行輸入處理「臨時會議插入／突發事件」，**只重排當天剩餘時段**，不重做整天規劃。針對每週 ~3 次臨時插入用，使用成本 10 秒。

## 是什麼 (What)

[[Prompt-腦清空與排程]] 的「微創手術版」：不動已執行的時段、只重排剩餘。

> [!note] 為什麼分開
> 整天規劃 prompt 很重（含 baseline 整貼、5 類分類、全天時段表）。一週 3 次的臨時插入用整版太浪費，分一個輕量版專處理。

## 何時用 (When)

- 適合：
  - 臨時會議插入（教授找開會、客戶突發 call）
  - 突發狀況需暫停 1-2 小時
  - 計畫已開始但中段被打斷
- 不適合：
  - 心情變動 → 接受少做就好，不需重排
  - 整天重新規劃 → 用 [[Prompt-腦清空與排程]]
  - 起床發現整週都要動 → 跑 [[Prompt-腦清空與排程]] 重排週版

## 怎麼做 (How)

### 1. 必填欄位

| 欄位 | 範例 |
| ---- | ---- |
| 原計畫剩餘項目 | 從原本的輸出剪下還沒做的 2-5 項（含原本分配時段）|
| 剩餘可用時間 | 從 14:00 到 22:00（扣晚餐後實際 7h）|
| 臨時事件 | 15:00-16:00 教授找開會 |
| 本日能量偏差 | +1 / 0 / -1（可省，預設 0）|

### 2. 完整 Prompt

````xml
<role>生產力策略師，回應冷靜直接、不囉嗦</role>

<context>
我已有今天的排程（剩餘項目如下），現在被臨時事件打斷。
請只重排「剩餘未做」部分，不動已執行的時段。
個人基線在 <persona_baseline>，不因臨時事件改變能量曲線。
請用繁體中文回應。
</context>

<persona_baseline>
[貼上 個人基線檔.md 的完整內容]
</persona_baseline>

<input_data>
原計畫剩餘項目：[貼上還沒做的 2-5 項，含原本分配的時段]
剩餘可用時間：[從 HH:MM 開始 到 HH:MM]
臨時事件：[幾點到幾點是什麼事]
本日能量偏差：[+1 / 0 / -1，可省]
</input_data>

<rules>
- 只重排剩餘時段，不動已執行的時段
- 臨時事件視為「責任-不可動」插入
- 剩餘時段若不足容納全部項目，列出「被擠掉」清單，每項一句話原因 + 建議重排到本週哪天
- 結論用肯定句
- 不重新評估能量等級，沿用 <input_data> 標示或 <persona_baseline> 第 4 節
</rules>

<output_format>
## 重排後的剩餘時段表
| 時段 | 類別 | 任務 | 預估時長 | 完成判準 |
| ---- | ---- | ---- | ---- | ---- |

## 被擠掉的項目（如有）
- [項目] — [一句話原因，建議重排到本週哪天]
</output_format>

<self_check>
- [ ] 已執行時段保持不變
- [ ] 臨時事件已正確插入指定時段
- [ ] 剩餘可用時間總長 = 各項預估時長之和（或被擠出來的有列出）
- [ ] 所有結論用肯定式
</self_check>
````

### 3. 使用 Tips

> [!tip]
> - 「原計畫剩餘項目」越具體越好，**含原本各項分配的時段**（讓模型知道哪些可移動）
> - 臨時事件 > 2 小時，多半會擠掉項目；接受被擠的清單，下次跑 [[Prompt-腦清空與排程]] 時補
> - 一日內被打斷超過 2 次 → 直接放棄重排，當天剩餘改休息／興趣
